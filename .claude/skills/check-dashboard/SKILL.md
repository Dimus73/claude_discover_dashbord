---

Выполни следующие шаги по порядку. После каждого шага запомни результат (OK или FAIL + детали). В конце выведи итоговый отчёт.

## Шаг 1 — Здоровье сервера

```bash
curl -s http://localhost:3001/api/health
```

Ожидаем JSON с полями `status`, `timestamp`, `uptime`. Если команда завершилась с ошибкой или вернула не JSON — FAIL.

## Шаг 2 — Метрики API

```bash
curl -s http://localhost:3001/api/metrics
```

Ожидаем JSON с полями `cpu`, `memory`, `uptime`, `requests`. Значения не должны быть `null`. Если поля отсутствуют или значения нулевые везде сразу — FAIL.

## Шаг 3 — Production-сборка клиента

```bash
cd /Users/dmitryprigozhin/repos/claude_discover_dashbord/client && CI=true npm run build 2>&1 | tail -20
```

Ожидаем строку `Compiled successfully` или `The build folder is ready`. Любые слова `ERROR` или ненулевой код выхода — FAIL.

## Шаг 4 — Открыть браузер

Используй Playwright. Перейди на `http://localhost:3000`. Дождись загрузки страницы.

## Шаг 5 — Проверить карточки

Сними accessibility snapshot страницы. Проверь, что:

- Присутствуют все 4 заголовка карточек: `CPU`, `Memory`, `Uptime`, `Requests`
- Ни одно числовое значение не равно `...` (три точки означают, что данные ещё не загружены)
- Значение CPU — число от 0 до 100
- Значение Memory — положительное число
- Значение Uptime — положительное число

Если хотя бы одна карточка показывает `...` — FAIL.

## Шаг 6 — Итоговый отчёт

Выведи таблицу:

| Проверка | Статус | Детали |
|---|---|---|
| Сервер /api/health | OK / FAIL | ... |
| API /api/metrics | OK / FAIL | значения cpu/memory/uptime/requests |
| Production build | OK / FAIL | ... |
| Браузер: 4 карточки | OK / FAIL | какие карточки видны |
| Браузер: нет "..." | OK / FAIL | какие значения отображаются |

Итог: **OK** если все строки OK, иначе **FAIL** — перечисли что именно сломано.
